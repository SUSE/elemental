# Changelog

## v3.1.0

Changes since `v3.0.0`. This includes the changes from the `v3.1.0-alpha.20260901` and `v3.1.0-alpha.20261117` pre-releases. Fixes that were also backported to the `release-3.0` branch are marked with the 3.0.x release that first shipped them.

### Highlights

- `elemental3 customize --airgap` builds images that bootstrap Kubernetes and deploy their workloads without network access. Helm charts, RKE2 images, and workload container images are embedded at customization time, and an embedded Hauler registry serves them on the node ([#593](https://github.com/SUSE/elemental/pull/593), [#637](https://github.com/SUSE/elemental/pull/637), [#647](https://github.com/SUSE/elemental/pull/647)).
- `elemental3 customize` caches downloaded artifacts and can run fully offline from a prepared cache with `--cache offline` ([#593](https://github.com/SUSE/elemental/pull/593)).
- Generated Ignition configuration is now shipped as Ignition base config inside an initrd extension, so platform-provided configuration such as cloud user-data can be merged on top of it ([#522](https://github.com/SUSE/elemental/pull/522), [#523](https://github.com/SUSE/elemental/pull/523), [#528](https://github.com/SUSE/elemental/pull/528), [#611](https://github.com/SUSE/elemental/pull/611), [#646](https://github.com/SUSE/elemental/pull/646)).
- Release manifests gained schema `v1`, with Elemental version metadata for Core Platforms and per-chart `priorityUpgrade`. `elemental3 customize` now checks that it is compatible with the selected Core Platform, and still supports Elemental 3.0 Core Platforms ([#534](https://github.com/SUSE/elemental/pull/534), [#635](https://github.com/SUSE/elemental/pull/635), [#631](https://github.com/SUSE/elemental/pull/631), [#646](https://github.com/SUSE/elemental/pull/646), [#644](https://github.com/SUSE/elemental/pull/644)).
- Elemental Lifecycle Manager is now required for Kubernetes deployments and is added by `elemental3 init` ([#639](https://github.com/SUSE/elemental/pull/639), [#559](https://github.com/SUSE/elemental/pull/559)).
- Cloud deployment support (Tech Preview), starting with AWS: external API load balancers, runtime node roles supplied through Ignition, and a Terraform demo deployment ([#578](https://github.com/SUSE/elemental/pull/578), [#579](https://github.com/SUSE/elemental/pull/579), [#601](https://github.com/SUSE/elemental/pull/601), [#602](https://github.com/SUSE/elemental/pull/602)).
- New output formats: a sparse `qcow2` image type with thin per-node overlays, and netboot artifacts for customized ISOs ([#653](https://github.com/SUSE/elemental/pull/653), [#590](https://github.com/SUSE/elemental/pull/590)).
- SLES 16.1 support: SELinux policy refresh during upgrades, no manual RKE2 SELinux module installation, and SELinux-compatible Hauler placement ([#618](https://github.com/SUSE/elemental/pull/618), [#626](https://github.com/SUSE/elemental/pull/626), [#647](https://github.com/SUSE/elemental/pull/647), [#651](https://github.com/SUSE/elemental/pull/651), [#660](https://github.com/SUSE/elemental/pull/660)).

### Breaking Changes

- When Kubernetes is enabled, `release.yaml` must list `elemental-lifecycle-manager` under `components.helm`; otherwise configuration validation fails ([#639](https://github.com/SUSE/elemental/pull/639)).
- `elemental3 customize` rejects Core Platforms whose Elemental version is incompatible or undefined. Supported are the same minor version as `elemental3` and the previous one, e.g. `elemental3` 3.1 accepts 3.0 and 3.1 Core Platforms. v0 manifests with a `metadata` block are treated as Elemental 3.0 ([#631](https://github.com/SUSE/elemental/pull/631), [#646](https://github.com/SUSE/elemental/pull/646)).
- `elemental3 customize --local` is now an alias for `--cache offline` and cannot be combined with another `--cache` mode. `customize` no longer reads images from local container storage or containerd. Seed the cache instead (see [Schema And Definition Changes](#schema-and-definition-changes)). `--local` keeps its previous meaning for the other commands ([#593](https://github.com/SUSE/elemental/pull/593)).
- For Elemental 3.1 Core Platforms, the Ignition configuration generated by `customize` is no longer written to `ignition/config.ign` on the config partition. It is embedded as Ignition base config in an initrd extension instead. As a result, the config partition is labelled `COMBUSTION` instead of `ignition`, unless the first-boot configuration provides `ignition/config.ign`. Tooling that looks up `LABEL=ignition` must handle the new label. Elemental 3.0 Core Platforms keep the previous behavior ([#528](https://github.com/SUSE/elemental/pull/528), [#611](https://github.com/SUSE/elemental/pull/611), [#646](https://github.com/SUSE/elemental/pull/646)).
- The deprecated `elemental3 build` command was removed. Use `elemental3 customize` ([#620](https://github.com/SUSE/elemental/pull/620)).
- When a Helm chart is defined in both the Core Platform and the Solution release manifest, the Core Platform definition now takes precedence ([#559](https://github.com/SUSE/elemental/pull/559)).
- `deployment.yaml` is now parsed strictly, and unknown fields cause an error. Files written by Elemental 3.0 remain valid ([#632](https://github.com/SUSE/elemental/pull/632)).
- When nodes are declared in `kubernetes/cluster.yaml`, Kubernetes configuration now fails on hosts whose hostname matches no declared node instead of silently falling back to the `server` role ([#564](https://github.com/SUSE/elemental/pull/564)).
- Helm charts in `kubernetes/cluster.yaml` can no longer use the name of a Helm chart defined in the release manifests as release name, even when that chart is not enabled, as the Elemental Lifecycle Manager would upgrade them to the release manifest chart. Set a different `releaseName` for such charts ([#474](https://github.com/SUSE/elemental/issues/474)).
- Release manifests using `schema: v1` must not set `metadata.version`. Existing `v0` manifests, including manifests without a `schema` field, are still accepted and migrated automatically ([#534](https://github.com/SUSE/elemental/pull/534)).

### Schema And Definition Changes

Release manifests can use schema `v1`. It drops `metadata.version` and adds optional Elemental version metadata to Core Platform manifests ([#534](https://github.com/SUSE/elemental/pull/534), [#635](https://github.com/SUSE/elemental/pull/635)):

```yaml
# Before (v0, still accepted)
schema: v0
metadata:
  name: suse-core
  version: "1.0"
  creationDate: "2026-11-10"

# After (v1 Core Platform manifest)
schema: v1
metadata:
  name: suse-core
  creationDate: "2026-11-10"
  elemental:
    version: "3.1"                                      # required when elemental is set
    image: registry.example.com/elemental/elemental:3.1 # optional
```

Helm charts in `v1` release manifests can request a priority upgrade by Elemental Lifecycle Manager. Priority charts are upgraded, together with their dependencies, before the OS, RKE2, and remaining Helm upgrades ([#644](https://github.com/SUSE/elemental/pull/644)):

```yaml
schema: v1
components:
  helm:
    charts:
      - chart: system-upgrade-controller
        version: 109.0.2
        namespace: cattle-system
        repository: rancher-charts
        priorityUpgrade: true
```

Kubernetes-enabled configurations must select Elemental Lifecycle Manager ([#639](https://github.com/SUSE/elemental/pull/639)):

```yaml
# release.yaml
components:
  kubernetes: {}
  helm:
    - chart: metallb
    - chart: elemental-lifecycle-manager
```

Air-gapped builds can embed additional images, authenticate to private registries, and provide API versions for Helm chart image discovery ([#593](https://github.com/SUSE/elemental/pull/593), [#664](https://github.com/SUSE/elemental/pull/664)):

```yaml
# kubernetes/cluster.yaml
helm:
  charts:
    - name: cert-manager-fips
      version: "1.19.3"
      targetNamespace: cmf-system
      repositoryName: application-collection
      apiVersions:
        - batch/v1
        - apps/v1/Deployment
embeddedRegistry:
  containerImages:
    - name: registry.rancher.com/rancher/shell:v0.5.0
  registries:
    - uri: registry.example.com
      credentials:
        username: user
        password: pass
```

Locally built images previously consumed through `customize --local` can be seeded into the cache ([#593](https://github.com/SUSE/elemental/pull/593)):

```shell
podman push localhost/release-manifest:dev oci:<PATH_TO_CACHE_DIR>/oci:localhost/release-manifest:dev
podman run -it -v <PATH_TO_CONFIG_DIR>:/config -v <PATH_TO_CACHE_DIR>:/cache $ELEMENTAL_IMAGE customize --type raw --cache offline
```

The Kubernetes API VIP can be served by an external load balancer. When no `nodes` are declared, node roles are read at boot from `/var/lib/elemental/runtime.env`, which can be supplied through runtime Ignition, e.g. cloud user-data ([#578](https://github.com/SUSE/elemental/pull/578)):

```yaml
# kubernetes/cluster.yaml
network:
  apiVIP: 10.0.1.50
  apiHost: api.cluster01.example.com
  apiVIPMode: external   # default: managed
```

```shell
# /var/lib/elemental/runtime.env
NODETYPE=server        # server | agent
IS_INIT_NODE=true      # only on the initializing server; defaults to false
```

ISO images can produce netboot artifacts ([#590](https://github.com/SUSE/elemental/pull/590)):

```yaml
# install.yaml
iso:
  device: /dev/sda
  netbootURL: http://localhost:8080/elemental.iso   # http://, https:// or nfs://
```

Deployment descriptions can define initrd extensions ([#522](https://github.com/SUSE/elemental/pull/522)):

```yaml
bootloader:
  name: grub
  initrdExtensions:
    - /path/to/initrd/extension.cpio
```

### Features

- Added `elemental3 customize --airgap`. It embeds the configured Helm charts as `chartContent` in their HelmChart resources. It also collects container images from templated Helm charts, Kubernetes manifests, release manifest chart image lists, and `embeddedRegistry.containerImages`, and stores them in an embedded registry ([#593](https://github.com/SUSE/elemental/pull/593)).
- Added RKE2 image embedding for air-gapped builds. Image lists are read from the `rke2-images-<set>.linux-<arch>.txt` files in the Core Platform Kubernetes image. The `core` set is always included, plus the configured CNI plugins and any non-default ingress controller ([#637](https://github.com/SUSE/elemental/pull/637)).
- Added `elemental-registry.service`, which serves air-gapped images with Hauler on port 6545 before RKE2 starts. The service is configured as the first mirror endpoint in `registries.yaml` for every registry the images come from. Image data lives in `/var/lib/elemental/registry`, and the Hauler binary is shipped by the OS image, so air-gapped images can also be customized for another architecture ([#593](https://github.com/SUSE/elemental/pull/593), [#647](https://github.com/SUSE/elemental/pull/647), [#663](https://github.com/SUSE/elemental/pull/663)).
- Added an artifact cache to `elemental3 customize` with the `--cache` (`auto`, `offline`, `refresh`, `off`) and `--cache-dir` options. OCI images are kept in an OCI layout under `<cache>/oci`, and downloaded files under `<cache>/files` ([#593](https://github.com/SUSE/elemental/pull/593)).
- Added the `qcow2` image type to `elemental3 customize` and `elemental3ctl build-installer`. Added `customize --overlay <name>` to create thin per-node `<name>.qcow2` overlays on top of the customized image ([#653](https://github.com/SUSE/elemental/pull/653)).
- Added netboot support. When `iso.netbootURL` is set, `customize --type iso` also produces a `<image>-netboot/` directory with the kernel, initrd, and GRUB EFI artifacts that boot the customized ISO from that URL ([#590](https://github.com/SUSE/elemental/pull/590)).
- Added initrd extensions to deployment descriptions and installer media. CPIO archives are loaded ahead of the OS image's stock initrd ([#522](https://github.com/SUSE/elemental/pull/522), [#523](https://github.com/SUSE/elemental/pull/523)).
- Added release manifest schema `v1`, with automatic in-memory migration of `v0` manifests ([#534](https://github.com/SUSE/elemental/pull/534), [#635](https://github.com/SUSE/elemental/pull/635)).
- Added `priorityUpgrade` for Helm charts in `v1` release manifests ([#644](https://github.com/SUSE/elemental/pull/644)).
- Added a compatibility check between `elemental3` and the Core Platform's Elemental version. It warns when `elemental3` is older than the Core Platform within the same minor version ([#631](https://github.com/SUSE/elemental/pull/631), [#646](https://github.com/SUSE/elemental/pull/646)).
- Added `releaseName` to the Helm charts of `kubernetes/cluster.yaml` to set their Helm release name, e.g. to deploy the same chart more than once ([#474](https://github.com/SUSE/elemental/issues/474)).
- Added `network.apiVIPMode: external` for API VIPs served by third-party load balancers. MetalLB and Endpoint Copier Operator are then not deployed ([#578](https://github.com/SUSE/elemental/pull/578)).
- Added runtime node role configuration through `/var/lib/elemental/runtime.env`, so a single customized image can boot as an initializing server, joining server, or agent ([#578](https://github.com/SUSE/elemental/pull/578)).
- Added Terraform automation under `terraform/` to deploy demo single-node and multi-node clusters on AWS with `make -C terraform up` ([#601](https://github.com/SUSE/elemental/pull/601)).
- Added AWS configuration directory and runtime Ignition examples under `examples/elemental/customize/aws` and `examples/elemental/runtime-configs` ([#579](https://github.com/SUSE/elemental/pull/579)).
- Added merge conflict reporting during upgrades. Files changed by both the user and the new OS image are listed in a warning, and the user version is kept ([#508](https://github.com/SUSE/elemental/pull/508)).
- Added `elemental-lifecycle-manager` to the `release.yaml` generated by `elemental3 init` ([#639](https://github.com/SUSE/elemental/pull/639)).
- Added an "Installer" row with the installer ISO image to `elemental3 release-info` ([#553](https://github.com/SUSE/elemental/pull/553)).
- Added `--platform` to `elemental3 release-info`, to inspect release manifest images published only for another architecture than the host one, e.g. `rke2-nvidia64kb-manifest`.

### Changes

- Changed `elemental3 customize` to create a cache under `<config-dir>/cache` by default when no directory is mounted at `/cache`. In the default `auto` mode, images are cached by reference, so mutable tags such as `latest` are served from the cache until `--cache refresh` is used ([#593](https://github.com/SUSE/elemental/pull/593)).
- Changed Ignition handling for Elemental 3.1 Core Platforms. The generated configuration and the translated `butane.yaml` are installed as `/usr/lib/ignition/base.d/10-elemental.ign` and `/usr/lib/ignition/base.d/90-butane.ign` in an initrd extension ([#528](https://github.com/SUSE/elemental/pull/528), [#646](https://github.com/SUSE/elemental/pull/646)).
- Changed Kubernetes provisioning to deliver all generated Kubernetes files under `/var/lib/elemental/kubernetes` through Ignition instead of the overlay tree ([#548](https://github.com/SUSE/elemental/pull/548)).
- Changed `k8s-resource-installer.service` to keep `/var/lib/elemental/kubernetes` after deploying resources instead of deleting it ([#552](https://github.com/SUSE/elemental/pull/552)).
- Changed `k8s-resource-installer.service` to give up after five failed starts within an hour instead of retrying forever ([#655](https://github.com/SUSE/elemental/pull/655)).
- Changed Elemental's base RKE2 configuration to the drop-in `/etc/rancher/rke2/config.yaml.d/00-elemental-base-rke2-config.yaml` instead of appending it to `/etc/rancher/rke2/config.yaml`. Per-node overrides belong in later drop-ins, e.g. `99-*.yaml` ([#578](https://github.com/SUSE/elemental/pull/578)).
- Changed customized images to always contain the init, joining server, and agent RKE2 configurations. Single-node clusters now use the init configuration and get a generated cluster token ([#578](https://github.com/SUSE/elemental/pull/578)).
- Changed `k8s-config-installer.service` to read the optional `/var/lib/elemental/runtime.env`. Without declared nodes, `k8s-resource-installer.service` runs only where `IS_INIT_NODE=true` ([#578](https://github.com/SUSE/elemental/pull/578)).
- Changed `k8s-config-installer.service` to stop installing the RKE2 SELinux module manually for Elemental 3.1 Core Platforms, where it ships preinstalled ([#626](https://github.com/SUSE/elemental/pull/626), [#646](https://github.com/SUSE/elemental/pull/646)).
- Changed Elemental Lifecycle Manager dependency handling: `system-upgrade-controller` is skipped when `rancher` is enabled, and `cert-manager` is skipped when the LCM values set `webhook.cert.createDefault: false` ([#559](https://github.com/SUSE/elemental/pull/559)).
- Changed default and generated system partitions to mount all read-write subvolumes (`/opt`, `/srv`, `/home`, `/usr/local`, in addition to `/etc`, `/var` and `/root`) in the initrd, so Ignition can write to them without redeclaring the `SYSTEM` filesystem ([#654](https://github.com/SUSE/elemental/pull/654)).
- Changed `elemental3 customize --output` to write `image-<timestamp>.<type>` inside the given path when it points to an existing directory ([#311](https://github.com/SUSE/elemental/pull/311)).
- Changed `elemental3 customize` to fail early when the output image already exists ([#532](https://github.com/SUSE/elemental/pull/532)).
- Changed the installer media of `elemental3 customize` to show the system journal on the first virtual terminal instead of a root shell, which moved to the second virtual terminal ([#339](https://github.com/SUSE/elemental/issues/339)).
- Changed the error for Helm charts missing from the release manifests to "helm chart is not defined in the core platform or solution release manifest" ([#654](https://github.com/SUSE/elemental/pull/654)).
- Changed `elemental3 customize` to log every Helm chart it deploys, including the ones from `kubernetes/cluster.yaml` with their version and repository, and to log each release Helm chart only once ([#448](https://github.com/SUSE/elemental/issues/448)).
- Changed the `elemental3` container image to include `helm`, `hauler`, `cpio`, and `qemu-img` ([#593](https://github.com/SUSE/elemental/pull/593), [#647](https://github.com/SUSE/elemental/pull/647), [#528](https://github.com/SUSE/elemental/pull/528), [#653](https://github.com/SUSE/elemental/pull/653)).
- Changed Kubernetes files that hold the cluster token or credentials to be readable by root only (`0600`): the RKE2 `server.yaml`, `init.yaml`, `agent.yaml`, and `registries.yaml`, HelmChart resources, Helm authentication secrets, and user manifests ([#661](https://github.com/SUSE/elemental/pull/661)).
- Changed `elemental3 release-info` to show the Elemental version of a Core Platform instead of an empty "Version" row ([#661](https://github.com/SUSE/elemental/pull/661)).
- Changed the fallback version of untagged builds from `v0.0.1` to `v3.0` and moved version information to the top-level `version` package. Packagers setting ldflags must use `github.com/suse/elemental/v3/version.version` and `github.com/suse/elemental/v3/version.gitCommit` ([#633](https://github.com/SUSE/elemental/pull/633)).

### Fixes

- Fixed "no space left on device" failures with large payloads. Recovery and config partitions are now sized with filesystem headroom that grows with the content ([#654](https://github.com/SUSE/elemental/pull/654)).
- Fixed `HelmChartConfig` resources for core RKE2 charts being applied too late. Manifests that contain only `HelmChartConfig` resources are now written to `/var/lib/rancher/rke2/server/manifests` with an `elemental-` prefix, so RKE2 applies them together with its core charts ([#655](https://github.com/SUSE/elemental/pull/655)).
- Fixed empty or malformed Kubernetes manifests breaking `k8s-resource-installer.service` on the booted node. `customize` now rejects manifests that contain no resource or a resource without `kind` or `apiVersion` ([#655](https://github.com/SUSE/elemental/pull/655)).
- Fixed installs hanging on large disks while systemd-repart discarded the disk. The disk is now discarded once with `blkdiscard` before partitioning (also in v3.0.3) ([#556](https://github.com/SUSE/elemental/pull/556)).
- Fixed `noCopyOnWrite` being ignored for btrfs read-write volumes such as `/var` (also in v3.0.1) ([#509](https://github.com/SUSE/elemental/pull/509)).
- Fixed `kubernetes/config/server.yaml` being ignored on single-node clusters that declare one node (also in v3.0.3) ([#481](https://github.com/SUSE/elemental/pull/481)).
- Fixed OCI Helm chart references when the repository URL ends with a slash. Invalid chart paths are now reported as errors (also in v3.0.3) ([#545](https://github.com/SUSE/elemental/pull/545)).
- Fixed `--verify=false` not disabling TLS certificate verification when pulling remote OCI images ([#583](https://github.com/SUSE/elemental/pull/583)).
- Fixed the installer ISO lookup for OS ISO images with non-default kernel flavors ([#640](https://github.com/SUSE/elemental/pull/640)).
- Fixed `elemental3 customize` panicking when the Core Platform release manifest has no `helm` section. A Core Platform without the `elemental-lifecycle-manager` chart is now reported as such instead of blaming `release.yaml` ([#661](https://github.com/SUSE/elemental/pull/661)).
- Fixed `elemental3 release-info` panicking on release manifests without a `metadata` section ([#661](https://github.com/SUSE/elemental/pull/661)).
- Fixed upgrades on systems with the SELinux policy store under `/etc/selinux` (SLES 16.1) by refreshing the policy before relabeling ([#618](https://github.com/SUSE/elemental/pull/618)).
- Fixed systemd-repart `EBUSY` failures in containers on all architectures by creating loop device nodes whenever running in a container ([#654](https://github.com/SUSE/elemental/pull/654)).
- Fixed images customized for another architecture than the customization host using the host architecture for the root partition type of RAW and qcow2 images and for the EFI boot file of netboot artifacts.
- Fixed the "Release Date" label in `elemental3 release-info` output (also in v3.0.2) ([#527](https://github.com/SUSE/elemental/pull/527)).
- Fixed `make clean` on macOS ([#494](https://github.com/SUSE/elemental/pull/494)).

Changes since `v3.0.0-alpha.20251212`.

In addition, `v3.0.0` includes the fix for deleted-file handling in the upgrade three-way merge ([#472](https://github.com/SUSE/elemental/pull/472)), examples switched to the stable `registry.suse.com` release paths ([#476](https://github.com/SUSE/elemental/pull/476)), and support for the renamed `base-os-kernel-default-iso` installer images ([#478](https://github.com/SUSE/elemental/pull/478)).

### Highlights

- RKE2 installation was reworked to use the standard install script and tarball workflow delivered through an OCI image instead of shipping RKE2 as a systemd extension ([#399](https://github.com/SUSE/elemental/pull/399)).
- Release manifests now distinguish Core Platform manifests from Solution manifests, replacing the previous Product terminology across APIs, examples, docs, and resolver code ([#462](https://github.com/SUSE/elemental/pull/462)).
- `elemental3 release-info` was added for inspecting release manifests from local files or OCI images, including readable table and Markdown output ([#392](https://github.com/SUSE/elemental/pull/392), [#407](https://github.com/SUSE/elemental/pull/407)).
- Configuration parsing is now schema-aware and validates image, deployment, Kubernetes, Helm, and release manifest definitions at parse time ([#375](https://github.com/SUSE/elemental/pull/375), [#379](https://github.com/SUSE/elemental/pull/379), [#421](https://github.com/SUSE/elemental/pull/421), [#360](https://github.com/SUSE/elemental/pull/360), [#365](https://github.com/SUSE/elemental/pull/365)).
- Kubernetes customization now supports `registries.yaml`, authenticated Helm repositories, safer config installation, and more robust resource deployment ([#429](https://github.com/SUSE/elemental/pull/429), [#387](https://github.com/SUSE/elemental/pull/387), [#443](https://github.com/SUSE/elemental/pull/443), [#439](https://github.com/SUSE/elemental/pull/439), [#411](https://github.com/SUSE/elemental/pull/411)).
- Local OCI extraction can use a running containerd daemon for already-unpacked images when `--local` and `CONTAINERD_SOCK` are both set ([#422](https://github.com/SUSE/elemental/pull/422)).

### Breaking Changes

- Configuration directories must declare the v0 schema in `install.yaml` ([#375](https://github.com/SUSE/elemental/pull/375)).
- Kubernetes cluster configuration moved from top-level `kubernetes.yaml` to `kubernetes/cluster.yaml` ([#370](https://github.com/SUSE/elemental/pull/370)).
- `release.yaml` no longer accepts the `name` field ([#436](https://github.com/SUSE/elemental/pull/436)).
- Product release manifest terminology was renamed to Solution. Example files and APIs now use names such as `suse-solution-manifest.yaml` and `pkg/manifest/api/solution` ([#462](https://github.com/SUSE/elemental/pull/462)).
- Kubernetes is now a first-class release-manifest component enabled with `components.kubernetes: {}`; RKE2 is no longer selected or represented as a systemd extension ([#399](https://github.com/SUSE/elemental/pull/399)).
- `elemental3 release-info` no longer provides YAML or JSON output modes. Use the source manifest YAML for machine-readable inspection, or table/Markdown output for readable summaries ([#407](https://github.com/SUSE/elemental/pull/407)).

### Schema And Definition Changes

Configuration directories now carry an explicit schema version ([#375](https://github.com/SUSE/elemental/pull/375)):

```yaml
# install.yaml
schema: v0
bootloader: grub
```

Kubernetes cluster configuration moved into the `kubernetes` directory ([#370](https://github.com/SUSE/elemental/pull/370)):

```yaml
# Before
# kubernetes.yaml
nodes:
  - hostname: node1.example
    type: server

# After
# kubernetes/cluster.yaml
nodes:
  - hostname: node1.example
    type: server
```

Release references changed from Product wording and RKE2 systemd extension selection to Solution wording and explicit Kubernetes selection ([#399](https://github.com/SUSE/elemental/pull/399), [#436](https://github.com/SUSE/elemental/pull/436), [#462](https://github.com/SUSE/elemental/pull/462)):

```yaml
# Before
name: suse-product
manifestURI: file://./suse-product-manifest.yaml
components:
  systemd:
    - extension: rke2
  helm:
    - chart: rancher

# After
manifestURI: file://./suse-solution-manifest.yaml
components:
  kubernetes: {}
  helm:
    - chart: rancher
```

Core release manifests now describe the Kubernetes distribution as a first-class component ([#399](https://github.com/SUSE/elemental/pull/399)):

```yaml
# Before
components:
  systemd:
    extensions:
      - name: rke2
        image: registry.example.com/rke2:1.34

# After
components:
  kubernetes:
    version: v1.35.0+rke2r1
    image: registry.example.com/rke2:1.35_1.0
```

Helm credentials can now be provided for release-selected charts and user-defined Kubernetes Helm repositories ([#387](https://github.com/SUSE/elemental/pull/387), [#443](https://github.com/SUSE/elemental/pull/443)):

```yaml
components:
  helm:
    - chart: endpoint-copier-operator
      credentials:
        username: release-user
        password: release-pass

kubernetes:
  helm:
    repositories:
      - name: private-charts
        url: https://charts.example.com
        credentials:
          username: user
          password: pass
        insecureSkipTLSVerify: true
```

Kubernetes configuration can include registry mirror settings ([#429](https://github.com/SUSE/elemental/pull/429)):

```yaml
# kubernetes/config/registries.yaml
mirrors:
  registry.suse.com:
    endpoint:
      - https://registry.suse.com/v2
```
